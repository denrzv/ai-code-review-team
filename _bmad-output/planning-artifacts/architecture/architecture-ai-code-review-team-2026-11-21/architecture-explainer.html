AI Code Review Team

How a review runs

A local experiment to see whether a Planner and focused reviewers find more defects than one reviewer given the same overall budget.

From two commits to a report

  1. The API pins the inputs. It checks an allowlisted synthetic repository and two commit IDs, freezes the budget, and returns a review ID to poll.
  2. Temporal chooses what happens next. In multi-agent mode a Planner proposes a task. Java checks the role, topic and budget before dispatch. In single-agent mode Temporal dispatches one reviewer.
  3. Reviewers inspect the pinned commits. Correctness, Security and Performance reviewers propose findings using bounded, read-only tools. Tool results show which changed lines the model actually received.
  4. The reporting Activity verifies citations. It checks candidate quotes against the policy-filtered HEAD, merges duplicates and publishes JSON, Markdown and a manifest. You can inspect rejected candidates and uncovered changes.

What happens if the worker stops?

Restart the worker with the same Temporal storage. Temporal reuses completed steps and can retry an interrupted Activity. The report shows observable retries and identifies usage that could not be recovered. A provider can bill a request it accepted before the worker lost the response.

How to read the comparison

A source-verified citation means the quote matched the pinned source. To judge whether a finding describes a defect, compare its root cause, location and failure scenario with the separate goldset. Pair runs on the same fixture and settings. Compare recall, precision, coverage, cost and latency, and keep partial or failed trials in the results.
